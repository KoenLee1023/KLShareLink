# KLShareLink 架构

## 概览

解析器位于不可信分享输入与接入应用导航/网络之间。它先验证显式 URL，再用 Foundation 检测文本候选，通过 URL scheme 和 host 检查后执行提供方匹配。没有 URL 时才检查旧版标记。策略是数据，副作用属于接入应用。

## 行为保证

- 通过过滤的显式 URL 优先
- 按文本出现顺序检测 HTTP(S) 候选
- 优先选择命中配置提供方的候选
- 拒绝 `localhost`、`.local`、`::1` 与文档列出的直接 IPv4 范围
- 无 URL 时可报告旧版提供方，但绝不虚构目标

## 职责边界

只负责选择输入，不发起请求、不展开重定向、不清理跟踪参数、不持久化历史，也不替网络层完成 SSRF 防护。除 `::1` 外，其他本地或私有 IPv6 直接地址不会被过滤器拒绝。网络层必须验证解析后的地址与每次重定向目标。

API 只返回计算结果，不会修改接入应用的状态。在输入、配置和系统框架行为一致时，结果保持一致。
